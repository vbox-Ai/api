## 三、架构建议：三层降级

```
homeContent
  ├─ 第1层：并发连通性探测（已实现）
  │    52 域名 3s 超时并发 → 只显示活的
  │
  ├─ 第2层：按平台类型路由 categoryContent
  │    mw      → HTML 解析（index-menu / /book/{id}）
  │    rryy    → HTML 解析（enter 门禁 + xpc-card）
  │    aijav   → 密文（等独立密钥）
  │    hxsp 系 → Spring Boot API（等签名）
  │    其余    → 标记"暂不支持"或隐藏
  │
  └─ 第3层：失败降级为"该平台暂不可用"，不返回空 error
```

**关键判断**：不要试图一次做全 52 个。真实可落地的是 **A 类 4 个**（mw 已通，
rryy 列表/详情通、播放限 VIP；km/91pron 需再攻）。其余靠"动态探测隐藏"处理，
用户看到的就是"能用的平台"，体验不崩。

## 五、通用技术要点（复用给后续平台）

| 场景 | 手法 |
|---|---|
| 门禁页 | 先 GET 门禁 URL 种 cookie，再访问内容页（`enter_site_ok`） |
| SPA 壳 | 找 `__NUXT__` / `window.__INITIAL_STATE__` / 搜 JS 里的 `/api/` |
| 403 反爬 | 加 `Referer` = 站点首页，`Origin` 同域；不行再试移动端 UA |
| 418 挑战 | 需要计算 JS challenge 或携带特定 cookie（如 `cf_clearance`） |
| 连接重置 | 该域名对非浏览器 TLS 指纹有检测，需要更完整的 header 伪装 |
| 空 body 200 | 需要 query 参数或签名，返回空是"参数不合法"的静默提示 |
