## 1. 目标与范围

### 1.1 目标

1. 在 vbox 福利专区出现 **2 个入口**：`X99视频导航`、`X99漫画导航`；
2. 进入入口后能看到该类型下所有平台（视频 26 / 漫画 3），每个平台有**分类筛选**和**线路选择**；
3. 列表 → 详情 → 播放/阅读全链路可用，播放地址失效时能自动换线路。

### 1.2 范围

| 类型 | 是否接入 | 数量 | 说明 |
| --- | --- | --- | --- |
| 视频 | ✅ | 26 | 对应福利专区「视频」栏目 |
| 漫画 | ✅ | 3 | 对应福利专区「漫画」栏目，走 `manga://` |
| 小说 | ⏸ 暂缓 | 1 | 方案留档附录 A，接口已确认可行 |
| 奶豆Ai | 🕒 靠后接入 | 1 | 方案 A：独立入口 `X99奶豆Ai`，排在视频/漫画之后（附录 D） |

### 1.3 完成标准（DoD）

- 远程源仓库 CI 四道校验全绿；
- App 内两个入口可见，tab 数量正确（26 / 3）；
- 每个接入平台：能出列表、能进详情、能起播（漫画为能翻页）；
- 任一平台故障不影响其他平台（异常隔离）。

## 2. 决策记录

已确认的决策，后续实现以此为准；有变更在此追加，不覆盖历史。

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 拆成 **视频 / 漫画 2 个平台入口** | 福利专区按 category 分区，视频与阅读器是两套 UI |
| D2 | **小说暂不接入**，方案留附录 A | category 只有 video/live/comic，小说归区需真机验证 |
| D3 | 入口域名与平台线路**用同一套优选机制** | 都是"并发探测，先可用者胜出" |
| D4 | **线路策略定为 A：轻量探测**（进平台时并发测 3 条，第一个 `ok` 即用） | 单次探测 200–400ms，比列表页开销小一个量级；原站"优选访问"证明线路质量参差 |
| D5 | 测速 **3 条一批、接力递进**；**不做后台补测**、**不"失败就全测"** | 拿到可用线路即停，省流量与 CPU，避免 WAF 判扫描 |
| D6 | 缓存 **600 秒**，到期后**重新并发探测** | 线路状态变化快，10 分钟是个平衡点 |
| D7 | 缓存地址失效：**乐观使用 → 失败即作废 → 死亡冷却 30 分钟 → 同次调用内接力** | 不做预检省往返；用户不能看到空页 |
| D8 | 探测预算：单条 4s、单平台 **12s（≈3 批 9 条）已确认** | 防整站全挂时界面转圈 50 秒；多数平台 ≤10 条线路，12s 足够测完 |
| D9 | 平台分类用 `filters` 的 chips 表达，不拆成上百个一级 tab | vbox 是"一级 class + 二级 filters"两层结构 |
| D10 | 生成器产出 **2 个自包含单文件 spider** | App 只加载单文件，不做跨文件 import |
| D11 | 奶豆Ai 采用**方案 A：独立入口** `X99奶豆Ai`（category=video），**排到视频/漫画之后** | 内容是"AI 作品流"，与影视站目录不同类；纯 JSON，实现简单（**已确认**） |

## 3. 现状

### 3.1 导航侧（已抓取并解析）

- 单页静态站，数据全在两个 base64 常量里：`headerData`（头部 HTML）、`encodedData`（站点 JSON）；
  解码链 `base64 → percent-decode → UTF-8`。
- 规模：**31 个平台 / 368 条线路**，每条线路含 `url` + `testUrl`。
- 线路可用判定：`testUrl` 返回字面量 `ok`。
- 原站"优选访问"实现：浏览器里对每条 `testUrl?ts=` 发请求，耗时 ÷2.5 当延迟，全部返回后选最小。
  **没有服务端接口**，结果只存在弹窗里 → spider 无法复用，只能自己探测（= 决策 D4）。
- 网络侧：`x99dh.net` 的 TLS SNI 在本机会被重置，`x99dh.lat` 可直连；
  原站对任何路径都返回 HTTP 500 但 body 是完整页面 —— **不能只看状态码**。

### 3.2 远程源仓库侧（已核实）

```
sources/manifest.json           App 启动入口，files.allSources → 聚合文件
sources/all_sources.json        聚合：apiSources/spiderSources/welfarePlatforms/...
sources/welfare_platforms.json  福利专区平台表（116 个）★ 加 2 条

domain-monitor/merge_sources.py 合并 all_sources.json
```

平台条目必填：`platformKey`（唯一）、`name`、`category`（∈ video/live/comic）、`icon`、
`serviceType`、`defaultHosts`（非空 http(s)）、`sortOrder`，Python 蜘蛛另加
`api` / `scriptType: python` / `engine: python` / `sslBypass` / `contentType`。

蜘蛛契约（宿主注入）：

```python
class Spider(SpiderBase):
```

宿主能力：`getCache/setCache`（跨调用持久）、`getProxyUrl(True)` + `localProxy({type,u,r})`（图片/播放代理）、
`manga://` / `novel://` / `pics://` 三种阅读器 scheme。

## 4. 架构

### 4.1 分层

```
vbox 福利专区
├─ 视频栏目：X99视频导航 (x99dh_video_py)   26 个平台 tab
└─ 漫画栏目：X99漫画导航 (x99dh_comic_py)    3 个平台 tab
        │
        ├─ L1 入口域名竞速    x99dh.net / x99dh.lat            600s 缓存
        ├─ L2 平台层          该类型下的平台 → 一级 tab
        ├─ L3 线路竞速        平台 urls[]，3 条一批接力          600s 缓存 + 死亡冷却
        └─ L4 适配器          maccms / missav / comic
```

### 4.2 UI 映射

```python
# 一级 tab = 平台；二级 chips = 该平台的分类 + 线路
homeContent(filter=True) -> {
  "class":   [{"type_id": "missav", "type_name": "MissAV"}, ...],
  "filters": {
    "missav": [
      {"key": "cate", "name": "分类", "value": [{"v":"20","n":"国产"}, ...]},
      {"key": "line", "name": "线路", "value": [{"v":"0","n":"自动"}, {"v":"1","n":"线路1"}, ...]}
    ]
  },
  "list": [各平台首页前 6 条混排]
}
```

`categoryContent(tid, extend={"cate","line"}, pg)`：`line=0` 走自动（策略 A），否则用指定线路。

### 4.3 运行时状态机

```
未缓存 ──探测(3条一批)──▶ 命中 ──写入缓存(600s)──▶ 直接使用
   │                        │
   │ 每批全挂                │ 使用中请求失败
   ▼                        ▼
下一批(≤预算)            缓存作废 + 死亡冷却(30min)
   │                        │
   └─ 全挂 → 回退旧胜者 ─────┴─ 同次调用内重新接力
                              └─ 仍失败 → 返回空列表（不抛异常）
```

## 5. 关键机制

### 5.1 入口域名优选（L1）

| 项 | 规则 |
| --- | --- |
| 候选 | `x99dh.net`、`x99dh.lat`（+ App 注入的覆盖域名） |
| 判定 | body 同时含 `encodedData` 与 `headerData`（**不看状态码**） |
| 胜出 | 并发请求，第一个成功者 |
| 缓存 | `x99dh:entry`，600s |
| 失败 | 全部失败 → 用上次胜者；再失败 → 用内嵌快照的平台列表 |

### 5.2 线路优选（L3）—— 策略 A：轻量探测

```python
LINE_STRATEGY = "A"      # A=轻量探测  B=免探测  C=混合（附录 B）
BATCH         = 3        # 每批并发条数
PROBE_TIMEOUT = 4        # 单条探测超时（status.html 很小）
PROBE_BUDGET  = 12       # 单平台探测总预算（秒）
CACHE_TTL     = 600      # 线路胜者缓存
DEAD_COOLDOWN = 1800     # 死亡线路冷却

def pick_host(platform):
    hit = cache.get(key)
    if hit and fresh(hit, CACHE_TTL):
        return hit.host                       # 600s 内直接复用，不探测

    for batch in batches(candidates(platform), BATCH):   # 3 条一批
        winner = race(batch, probe, PROBE_TIMEOUT)       # 批内并发，先 ok 者胜
        if winner:
            cache.set(key, winner)                       # 有结果即停，不补测
            return winner
        if budget_exceeded():                            # 预算耗尽就收手
            break
    return hit.host if hit else candidates(platform)[0]  # 回退，别让 UI 空着
```

为什么是这套参数：

- **不全测**：41 条并发打同一批域名容易被 WAF 判扫描；我们要的是"一条现在能用的"，不是全网排名。
- **不后台补测**：已经能用了，再探测就是纯消耗（流量/CPU/风控概率）。
- **接力而非一次全上**：探测规模恒定为 3 个并发，随着批次递进扩展，不放出连接风暴。
- **预算上限**：整站全挂时，41 条 × 3 条一批 ≈ 14 轮，不设上限会卡界面 50 秒以上。

### 5.3 缓存与失效

| 键 | 内容 | TTL | 过期/失效动作 |
| --- | --- | --- | --- |
| `x99dh:entry` | 入口域名胜者 | 600s | 重新并发请求两个域名 |
| `x99dh:line:{platform}` | 平台线路胜者 | 600s | 重新 3 条一批接力 |
| `x99dh:dead:{platform}` | 死亡线路 + 时间 | 1800s | 过期重回候选 |
| `x99dh:nav` | 平台/线路快照 | 6h | 重新拉导航；失败用内嵌快照 |
| `x99dh:cats:{platform}` | 分类 chips | 24h | 重新抓分类页 |

**缓存地址挂了怎么办（D7）**：

| 场景 | 处理 |
| --- | --- |
| 600s 内命中 | 直接请求，不预检（省往返） |
| 请求失败（超时/连接重置/403/5xx/内容标记缺失） | 缓存立即作废；该 host 进死亡名单（冷却 30 分钟） |
| 同一次调用内 | 当场接力下一批线路重测，不把空页返回给用户 |
| 播放直链 403/过期 | 换线路 → 重新取详情页 → 再解一次直链 |
| 全部失败 | 返回空列表（不抛异常），下次进入重测 |

### 5.4 异常隔离

- 适配器内部 `try/except` 兜底，任何异常都转成空结构返回；
- 平台 A 的适配器抛错不影响平台 B；
- 蜘蛛不向 App 抛栈，只记日志。

### 5.5 播放链路

```
detailContent → vod_play_from / vod_play_url（名$地址#…）
playerContent(flag, id) → 现取详情页 → 解 player_aaaa / m3u8 正则
  ├─ 直链可用 → {"parse":0, "url": "https://...m3u8", "header": {Referer, UA}}
  ├─ 需要 Referer → 直连 + header；若仍 403 → localProxy
  └─ 漫画 → {"parse":0, "url": "manga://img1&&img2"}
```

## 6. 适配器

### 6.1 接口

```python
class BaseAdapter:
    kind = "video"                  # video / comic
    def categories(self) -> list    # [{"type_id","type_name"}]
    def list(self, cate, page) -> dict
    def detail(self, vod_id) -> dict
    def play(self, flag, url) -> dict
```

### 6.2 三个实现

| 适配器 | 覆盖 | 关键点 |
| --- | --- | --- |
| `maccms` | 321AV、rouAV、黄色仓库、爱漫岛 | `/vodtype/{id}-{page}-{sort}.html` 列表；`.vodDetail`；`player_aaaa` 的 `url/encrypt`（1=unquote，2=base64） |
| `missav` | MissAV、Hanime1、好色TV、肉视频、Jable、Xanimu、CartoonPorno、avjoy、YesPorn、SuperPorn、亚洲素人精选 | `.group` 卡片；`og:title`；搜索 `/vodsearch/{kw}----{p}/`；每站一个 Profile |
| `comic` | 禁漫天堂、99漫画、爱漫岛 | `/album/{id}`；章节图 → `manga://`；18comic 图片分片解密 |

### 6.3 Profile 示例

```python
PROFILES = {
  "MissAV":  {"kind": "missav", "list": ".group", "search": "/vodsearch/{kw}-------------{p}/"},
  "321AV":   {"kind": "maccms", "list": "/vodtype/{id}-{page}-1.html"},
  "禁漫天堂": {"kind": "comic",  "album": "/album/{id}"},
}
```

Profile 外置成配置：站点改版只改配置，不改代码；未知平台默认按 `maccms` 试，取不到就返回空列表。

## 7. 生成器与仓库接线

### 7.1 流程

```
1. fetch  → 抓导航（复用 x99dh 包的 SNI 兜底），得 31 平台 / 368 线路
2. probe  → 并发测 testUrl，得线路排名
3. scan   → 跑一次 categories()，产出分类 chips（失败留空）
4. emit   → x99dh_nav.json（全量快照，含 kind）
             welfare-js/x99dh_video.py（内嵌 video 子集）
             welfare-js/x99dh_comic.py（内嵌 comic 子集）
             welfare_platforms.json 追加 2 条
5. merge  → merge_sources.py 合并 all_sources.json

```

### D.1 它到底是什么

不是影视站，是 **AI 成人内容生成社区**（站点标题 `NudeAI`）：

### D.2 接口实测

| 接口 | 鉴权 | 说明 | 可用 |
| --- | --- | --- | --- |
| `GET /plaza?offset=0&limit=20` | 无 | 广场作品流，返回 `{ok,data:[...]}` | ✅ |

### D.5 限制与风险

1. **没有标题/标签**：只有作者名和点赞数，列表可读性一般；
2. **分页靠 offset**：没有 total，翻到末尾返回空数组，需要靠"空页即停止"判断；
3. **短视频区（shorts）不可用**：要登录 + 积分（1000 积分/条），游客拿不到；
4. **角色/生成器不可用**：401，属于创作功能，不是浏览内容；
5. **内容为 AI 生成**：画质/时长参差，视频多为 5–20 秒；
6. **API 域名独立**（`api.vcjuligi.com`）：换域名时 `config.json` 会跟着变，蜘蛛应该**先读 config.json 再请求**，
   不要把 apiBase 写死。

### D.6 工作量

纯 JSON 接口，无 HTML 解析、无加密、无防盗链 —— 比任何一个影视站都简单：

- 蜘蛛实现：约 150 行（含 filters、offset 分页、两种播放形态）；
- 生成器只需多一个 `kind="ai"` 分支；

## 十四、性能优化模式（可复用到其他资源平台）

> 这套组合拳已在 X99 源上验证，后续接入新平台按此照搬即可。

### 14.1 首屏分类：快照 + 后台刷新

```
homeContent（2ms，纯内存）
  ├─ 立即返回快照里的平台与二级分类
  └─ 起 daemon 线程，每批 4 个平台抓 /enter 解析分类
       └─ 写入 x99dh:cats:{平台}，24h 有效
下次进入 → 直接读实时缓存（自适应且不拖慢首屏）
```

要点：**永远不要在 `homeContent` 里做网络请求**。App 把它当首屏探针，一旦慢了整页卡加载态。

### 14.2 连接复用：按域名的 TLS keep-alive 池

```python
_POOL = threading.local()          # 每线程独立，避免并发串包
conn = http.client.HTTPSConnection(host, context=_SSL)
conn.request("GET", path, headers=hdrs)   # 同域名复用，省 300-400ms 握手
```

配套：`Connection: keep-alive`、`Accept-Encoding: gzip`（58KB→16KB）、
`resp.will_close` 时丢弃重连、断连重试一次、3 跳内跟随 302。

### 14.3 列表缓存：单键 + TTL + 上限

`x99dh:lists = { "平台|分类|页": {"data":…, "ts":…} }`

- TTL 180s；
- 写入前清理过期项，再按时间裁剪到 **40 条**（≈100–300KB 封顶）；
- 避免"每键一条、只过期不删除"导致长会话内存只涨不降。

### 14.4 预测性预取：点一个分类，顺带热身相邻分类

列表返回后，后台抓同平台**接下来 2 个分类**并写入同一缓存（10 分钟内每平台只做一次）：

```
用户点「有码影片」→ 1800ms，返回
后台预取「无码影片」「中文字幕」→ 用户再点什么都是 0ms
```

### 14.5 效果

| 环节 | 优化前 | 优化后 |
| --- | --- | --- |
| 首屏分类 | 需网络 | **2ms** |
| 首次列表 | 2.3s | 0.9–2.3s（跨境 TLS + 143KB HTML 的物理下限） |
| 同平台换分类 | 每次 1–2s | **预取后 0ms** |
| 内存 | 只涨不降 | **≤1MB 封顶** |
