## 二、6868 主后端完整解密链路（本轮打通）

这是本轮最大突破：**此前一直卡在"响应是密文"，现在完整解出明文。**

### 链路

```
HTTP 层：Transfer-Encoding: chunked（带 16 进制长度前缀）
   ↓ 去帧
body：带双引号的 base64 字符串  "..."
   ↓ 去引号 + base64 解码
密文：3088~9088 字节，16 字节对齐
   ↓ AES-128-CBC
  key = "8992d27bceae2962"   ← 16 字符 ASCII，不是 hex！（此前误按 hex 处理导致 8 字节）
  iv  = "62233532ac9029c6"   ← 同上
   ↓ 得到 gzip 流（1f 8b 08 开头）
gzip 解压 → JSON 明文
```

### 关键坑（已解决）

1. `AES_KEY` 必须按 **ASCII 16 字符** 处理，`bytes.fromhex()` 会得到 8 字节并抛 `Invalid key size (64)`。
2. gzip 头正确不代表能 `gzip.decompress`——本样本 gzip 尾部有瑕疵，必须用 `zlib.decompressobj(-15)` 从第 10~16 字节偏移软解。
3. 响应头 `Content-Type: application/json` 但 body 是密文，容易误判。

### 6868 主后端鉴权头（明文抓包实证）

| 端点 | 方法 | 必需头 |
|---|---|---|
| `/box/api/ping` | GET | `user-agent`（免鉴权，返回 32B base64） |
| `/box/api/splash` | GET | `user-agent` `time`(13位毫秒) `uuid`(32位hex) |
| `/box/api/home?versionCode=101` | GET | 同上 |

`uuid` 每次请求都不同（`d755bf7c4ec961489a507813caf10272` / `3d386c86aa2036b6e1b1bd80b22858ee` / `2fcd8da48f573daa7250978f884f4c8d`），是**每请求随机 32 位 hex**，不是设备号。

## 八、对 hgsp 攻坚的直接影响

本轮证据推翻了一个假设、锁定了一个事实：

| 结论 | 证据 |
|---|---|
| hgsp host 确认为 `api55.nmrgqb.com` | splash 下发 + plist 双重印证 |
| `CBC(key, iv="16-Bytes--String")` 是这套全家桶的通用模式 | `cgw` 模块也出现同一常量 |
| `pkg` 头是 666 的触发源 | 单变量矩阵实验 |
| **缺的不是签名，是某个"头→参数"的映射** | `For input string: "nul"` 只在改 pkg/删 Seq 时消失 |

`"nul"` 的成因：Spring 侧 `StringUtils.substring(null,0,3)`。即**某个请求头的值为 null**，被 `Integer.parseInt` 吃了。
结合网关白名单（≤6 头）与业务需要（>6 头）的矛盾，唯一出路是拿到真机实际发送的头集合。

## 八之二、6868 主后端在线状态实测（本轮新增）

11 个 IP 全部在线，`/box/api/ping` 免鉴权可用：

```
38.46.10.2/3/4/5/6、122.10.20.249、198.44.248.101/102、202.95.22.200/201/202
→ 全部 200，返回固定 32B base64：FpEnw1XCDkamawKI7+yNhTnr0jzym8ZcI26bm2LlSiY=
```

`/box/api/splash` 与 `/box/api/home` 返回 `{"code":400,"msg":"违规请求","data":null}`。

### 错误分支已完全摸清

| 请求 | 返回 |
|---|---|
| 缺 `time` | `缺少请求头:time` |
| 缺 `uuid` | `缺少请求头:uuid` |
| `time` 早于现在（-1s 至 -1h、秒级格式） | `请求已过期` |
| `time` 等于现在（±10s 内均测） | `违规请求` |

### 判定

- 不是 IP 归属问题：本机出口 = **重庆电信 AS134420**（正是手机运营商网络），走代理也一样
- 不是头名大小写：原始 socket 全小写（抓包同款）/首字母大写/全大写，结果一致
- 不是 uuid 形态：32hex、大写、标准 UUID、plist 设备号、md5 派生，全部「违规」
- 不是 UA：4 种 UA（含抓包同款 `Dart/3.12 (dart:io)`）全部「违规」

**反汇编终审**：`avbox/module/box/network/interceptor.dart` 只 set 了 `time` 和 `uuid` 两个头，
不存在第三个必需头（字面量清单：`'time'`、`'uuid'`、`'arp'`、`'token_box'`、`'token'`）。

**结论**：6868 splash/home 在本轮期间被服务端加固（抓包时间为 2026-10-29，当时只需 time+uuid）。
这条"自取最新 host/token"的路暂时封死。已有数据仍然有效——host 表可直接用于适配。

> 影响面：`splash` 只用于拿 host/token 初始表，不参与平台数据请求。各平台 host 已知，
> 因此**不影响**任何平台适配工作。真正阻碍仍是各平台自身的签名/加密。
