# 暮色(avbox) 逆向全流程方法

> 目标 App：暮色 iOS 1.0.1（com.look.avbox）/ 安卓 1.0.1（com.look.mbox）
> 最终成果：AES-128-CBC 响应解密密钥 + 请求签名算法 + RSA 密钥对 + 52 平台路由
> 本文是该次逆向的**方法论沉淀**，App 更新后按此流程复用即可，不必从零摸索。

---

## 〇、架构总览（先记住这个再动手）

暮色是 **Flutter AOT 薄客户端 + 双后端**：

```
暮色 App (Flutter AOT, libapp.so / App)
   │
   ├─ ① box 后端（当前主用）：明文 HTTP :6868，多 IP 集群
   │     鉴权 = time(13位毫秒) + uuid(32位hex随机) + 可选 token
   │     响应 = base64(AES-128-CBC(gzip(JSON)))     ← 密钥在客户端二进制里(混淆)
   │     接口：/box/api/ping | /splash | /home | /collect/api/status
   │     风控：服务端按来源 IP 校验，PC/非手机网络返回 {"code":400,"msg":"违规请求"}
   │
   └─ ② api.* 旧通道（已废弃）：HTTPS api.3459381.com 等 5 域名
         鉴权 = X-Auth-Key/TimeStamp/Nonce/Sign 四件套（MD5(APP_KEY+ts+nonce)）
         实测已全部 500/404，仅留作兼容

另：37 个资源模块(91AV/四虎/MissAV/漫蛙...)各自还有独立平台域名，
    存于设备 plist / App 数据目录（暮色壳只做入口聚合，内容在各平台站）。
```

## 一、阶段 1：静态信息提取（半天）

**产出：域名池、平台清单、存储键名、候选密钥。**

1. **IPA/APK 解包**
   - iOS：`Payload/Runner.app/`，重点 `Frameworks/App.framework/App`（Dart AOT，看 cryptid 是否已脱壳）
   - 安卓：unzip APK → `lib/arm64-v8a/libapp.so`（Dart AOT 主快照，**安卓版通常不脱壳即可分析**）
2. **字符串提取**：`strings -n 8` 或 Python 正则扫二进制，得到：
   - 后端 IP 池（6868 端口族）
   - 100+ 个 API 路径（`box/api/*`、`api/v2/*`、`txapi/*` 等）
   - 加密函数名（`_encryptBlock@xxx`、`_generateSign@xxx`）
   - 加密库证据（`package:encrypt`、`package:pointycastle`）→ 确认 AES 在 Dart 层
3. **设备数据导出（决定性）**：越狱机 plist / 安卓 `/data/data/<pkg>/shared_prefs`：
   - 平台真实域名映射（暮色 plist 87 键含 52 平台基址）
   - 平台登录 token（JWT）
   - 图片 CDN 映射（BoxImageCache.json）
4. **sqlite 抓密文样本**：App 数据目录的 `.sqlite` 里存有历史响应密文，
   提取 base64 样本备用（验证密钥时的"已知明文"素材）。

> 教训：此阶段能拿到的一切明文信息都拿，但**不要在这里穷举密钥**——
> 本次穷举 5.5 万组组合（34 万字符串 × 全 AES 模式）0 命中，白费一整天。
> 密钥被混淆，纯字符串搜索永远找不到。

## 二、阶段 2：真机抓包定协议（半天）

**产出：确认哪个后端是"活的"、鉴权头格式、响应密文形态。**

1. 工具：Stream / Quantumult X / Reqable（iOS）；HttpCanary（安卓）
2. 确认点：
   - 业务请求走哪个 IP:端口（本次：`38.46.10.6:6868` 明文 HTTP）
   - 请求头全集（本次仅 5 个：`user-agent: Dart/3.12 (dart:io)`、`time`、`accept-encoding`、`uuid`、`host`）
   - `uuid` 每次随机 → 非设备指纹，可任意生成
   - 响应体形态：JSON 字符串包裹的 base64 → AES 密文
3. **风控验证**：PC 重放同请求 → 若返回 `违规请求` 说明服务端按来源 IP 校验。
   → 含义：逆向验证必须在手机网络环境做，PC 只能做离线解密。

## 三、阶段 3：密钥穷举（跳过！历史教训）

| 曾做过的尝试 | 规模 | 结果 |
|---|---|---|
| 二进制 ASCII 子串(16/24/32)当密钥 | 341,127 | ✗ |
| 二进制原始字节滑窗 | 4,328,585 | ✗ |
| 字符串 md5/sha1/sha256 派生 | 124,434 | ✗ |
| UUID/token/域名派生 | 508 | ✗ |
| ECB/CBC/CTR/CFB/OFB/GCM 全模式 | — | ✗ |

**结论：密钥不在明文里。别再穷举，直接走阶段 4 反编译。**

唯一值得保留的穷举验证脚本是"已知明文首块校验"：
拿到密钥候选后，用密文首块 + 猜测明文前缀（`{"code":0,` 等）做快速筛选。

## 四、阶段 4：Blutter 反编译破密（核心，1-2 天）

### 4.1 工具链搭建（Windows）

| 组件 | 版本要点 | 坑 |
|---|---|---|
| VS Build Tools | C++ 桌面开发工作负载 + Windows SDK | 必装 |
| cmake | ≥ 3.24 | |
| ninja | 最新 | |
| Python | requests 库 | `pip install requests` |
| ICU | 73.x 源码（用 gh-proxy 加速下载） | 编译/链接时 icuuc.lib 路径要指向 external 目录 |
| Dart SDK | **必须与 App 的 Flutter 版本匹配**（从二进制字符串看 snapshot hash 确认，本次 3.12.2） | 版本不匹配 Blutter 直接拒跑 |

### 4.2 五个必踩的坑（本次实录）

1. Blutter 脚本缺 `requests` → pip 装
2. MSVC 默认预处理器不支持 `__VA_OPT__` → 加 `/Zc:preprocessor`
3. 源码含 Unicode 字符（∞ 等）→ 加 `/utf-8`
4. ICU 库找不到 → icuuc.lib 路径显式指向 Blutter 的 external/icu 编译产物
5. Dart SDK 版本不匹配 → 用 `strings libapp.so | grep "Dart VM version"` 确认

### 4.3 反编译产出

```
blutter <libapp.so路径> <输出目录>
→ 输出 asm/（带符号的反汇编）、objs/（对象池）、pp.txt（字符串池）
```

重点搜：
- `StringExtension` 类（混淆函数所在，本次是 `s()` 方法）
- `interceptor.dart` 对应的反编译文件（onRequest/onResponse 加解密逻辑）
- `AESEngine` / `Encrypter` 的调用点（Key/IV 参数来源）

### 4.4 本次破解成果（示例，作为"读出来的样子"）

```dart
// interceptor.dart onResponse —— 响应解密
// 混淆真相：切罗基字母常量 → 逐码元 XOR 0x1395 → hex 字符串
String s(String src) => String.fromCharCodes(
    src.runes.map((r) => r ^ 0x1395));

// "ᎭᎬᎬᎧᏱᎧᎢ᏷᏶ᏰᏴᏰᎧᎬᎣᎧ" --XOR 0x1395--> "8992d27bceae2962" (Key)
// "ᎣᎧᎧᎦᎦᎠᎦᎧᏴ᏶ᎬᎥᎧᎬ᏶Ꭳ" --XOR 0x1395--> "62233532ac9029c6" (IV)
// 数据流：base64 → AES-128-CBC 解密 → gzip 解压 → JSON

// onRequest —— 请求加密
// Key = MD5("/" + path + 盐)，盐 = "1f2b2cd0f9503f960c2ad3f0194b4175"（同样 XOR 混淆）
// IV  = "${time}arp"（time 为 13 位毫秒时间戳）
// 另有 RSA-2048 密钥对用于 X-Auth-Sign（PKCS#8 PEM 内嵌于二进制）
```

## 五、阶段 5：一键化（App 更新后从此秒级）

混淆模式（切罗基 UTF-16LE + XOR 掩码）一旦确认，就**不再需要 Blutter**：
直接对 libapp.so 做字节级模式匹配即可。工具：

```bash
python tools/crack_muse_key.py 暮色新版.apk
# 秒级输出 AES_KEY / AES_IV（详见 docs/密钥一键提取指南.md）
```

脚本特性：
- 已知掩码 0x1395 秒出；若暮色换掩码，自动暴力 0x0000~0xFFFF 探测
- 支持 APK / libapp.so / iOS App 三种输入
- 独立 16 长常量自动判 Key/IV（对象池布局：offset 小者=IV）

只有当脚本**完全 0 命中**时（说明混淆算法整个换了），才回退阶段 4 重跑 Blutter。

## 六、阶段 6：Frida 动态验证（可选加速器）

静态分析拿到密钥后，用 Frida 在真机上做最终验证（也可独立拿密钥）：

```js
// 思路 1：搜 AES S-box(256字节固定表) 定位 AESEngine，hook init dump key
// 思路 2（更快）：hook 解密函数出口，直接 dump 解密后的明文 JSON
//   → 顺带解决"响应字段结构未知"问题（见 muse_avbox 蜘蛛适配篇）
```

Frida 不依赖反编译，对"运行时才派生的密钥"是唯一解；但对硬编码混淆密钥，
静态一键脚本（阶段 5）更快。两者互补。

## 八、下次暮色更新时的 SOP（5 分钟）

1. 下载新版 APK
2. `python tools/crack_muse_key.py 新版.apk`
3. Key/IV 填入 `sources/welfare-js/muse_avbox.py` 的 `AES_KEY`/`AES_IV`
4. 若脚本 0 命中 → 回退本文件阶段 4（Blutter 全量）找新混淆算法
5. 提交推送远程源仓库（**记得跑 `domain-monitor/merge_sources.py` 同步 all_sources.json**）
