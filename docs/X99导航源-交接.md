## 三、适配器架构（新增平台必读）

### 3.1 接口约定

```python
class _FooAdapter(_BaseAdapter):
    def categories(self):   # 可选：返回 [{"type_id","type_name"}]，Spider 会缓存 24h
    def list(self, cate, page) -> {"list":[vod...], "page":int, "pagecount":int}
    def detail(self, vid)      -> {"list":[vod]}   # vod 里 vod_play_url 用 "名称$key::目标"
    def play(self, flag, url)  -> {"parse":"0", "url":..., "header":{...}}
```

- `vod_id` 格式固定 `平台key::自定义id`，`detail`/`play` 收到的是 `::` 后面的部分。
- `vod_play_url` 多集用 `#` 分隔，单集写 `正片$key::<目标>`；目标是 URL 就直接给 URL，
  是 id / 详情页地址就在 `play()` 里现取（VJAV / XVIDEOS / KVS / 99漫画 就这么做）。
- 图集用 `pics://url1&&url2&&...`（Hentai / 禁漫 / 爱漫岛 / 99漫画）。
- 注册：`nav/registry.py` 的 `ADAPTERS` 加一行 + tpl 的 `ADAPTERS` 字典加一行。
- **平台级 Tab 会把 `cate` 传成 `"0"`**（因为 `categoryContent` 在没有快照分类时兜底成 `"0"`）。
  分类 id 非纯数字的适配器必须挡掉：`if cate.isdigit(): cate = ""`（XVIDEOS 本轮踩过）。

### 3.2 分类运行时补全（第十一轮机制）

`Spider.cats_for(platform)` 三级回退：**运行时缓存 → 快照 classes → 适配器 `categories()`**。
快照扫描只认老式 `vodtype` 路径，所以新平台必须实现 `categories()`，否则 UI 只有一个 Tab。
**现在 26/26 家都有分类**。

### 3.3 请求层

`self.s.http(url, referer=..., headers={...})`：连接复用 + gzip + 4xx/5xx 读 body + 3 跳重定向。
各适配器自带 `_page()` 包一层，加 UA / 壳页重试 / 多线路兜底。
`_BaseAdapter._abs()` 已支持协议相对地址 `//host/path`（第十二轮修）。

## 五、关键逆向成果（这些别重做）

### 5.1 大哥视频（Vue SPA + 自定义加密）

```
接口：baseURL=/api
  /api/core.json            → menu（分类树，32 个 vod 分类）
  /api/index.json           → 首页
  /api/lists/{id}/{page}/{limit}.json
  /api/play/{id}.json       → player[0].play = m3u8

响应 data 字段解密（Python 复刻）：
  t = data.replace("/","0").replace("@","/").replace(".","+")[::-1]
  t += "=" * ((4 - len(t) % 4) % 4)
  json.loads(base64.b64decode(t))
  # 顺序必须是 /→0、@→/、.+→+，然后整体反转，最后补 =
```

### 5.2 18av（AES 播放 id）

```
详情页 mvarr['10_1'] 第二段 = baseN 串（N=hcdeedg252）
→ int(p, N) ^ hadeedg252 → base64
→ AES-128-CBC 解密（key=argdeqweqweqwe, iv=hdddedg252，页内 16 位 hex）→ player id
→ /js/player/play.php?numresolution=1080&id={id} → 720/1080 m3u8
```
纯标准库 AES 已内置在 tpl（`_aes_cbc_decrypt`）。

### 5.3 肉视频 / 爱漫岛 / 禁漫（自定义编码）

- 肉视频：`ev:{d,k}` → `base64(d)` 每字节 `-k` → JSON `{videoUrl:"/api/hls/{id}"}`
- 爱漫岛：`player_aaaa.url` 双层 JSON → `aid`+`s2`，图 = `/jmpimg/cdn-msp.{dom_string}/media/photos/{aid}/{page:05d}.webp`，
  `dom_string` 取页内**最后一次赋值**
- 禁漫：图片 `media/photos/{aid}/{page:05d}.webp`；`scramble_id` 分块重排只影响单图，不影响 URL 序列

### 5.5 XVIDEOS 壳页自举（第十二轮）


   （18av 的 `chinese_search` 就是这么找到的）。
6. **禁漫图片分块重排**——`scramble_id=220980` 时 aid 超阈值需客户端算法还原单图；
   目前传原始 URL 序列（顺序正确、内容完整）。
7. **Hentai 同册后缀一致性是小样本结论**——抽样两个画廊 31 页全是 `.webp`；
   若某册混用 `.jpg/.png`，按页号拼出来的少数几张会 404（可退化为逐页抓阅读页）。
   遇到再处理，并**先做内容级比对**再决定。
8. **基类 `_backup_hosts` 自动回退没用**——基类 `_request()` 会在主域名失败时自动切备用域名，
   我们走自己的 `_http` + `_LinePicker`（361 条线路）大致等价，但没复用基类机制。
   `_apply_proxy()` 代理注入已补上；这条回退机制**暂不补**，除非有真机反馈。
9. **捷报：`searchContent` 已完成**（第十二轮补充②）。原来这里是"最大空白"，现已落地 8 家平台，
   详见第五节 5.7。**这一步顺带确认了它属于福利专区、与普通视频契约级隔离**。

## 八、踩过的坑（新会话别重复）

1. **2337 字节响应 = 壳页**，但**成因有三种**：cookie 自举（XVIDEOS，带 cookie 即过）、
   首页专用（Hanime1，换 `/watch?v=` 路径即可）、频率限制（99漫画，退避重试）。
   **别一律判「反爬失败」** —— 先试「带 `x-index-auth=authed`」「换内容路径」「退避一次」。
2. **HTTP 4xx/5xx 也要读 body**：`_http` 已实现；自己写探针时 `except HTTPError` 里要 `exc.read()`，
   否则会把「500 + 完整页面」误判成失败（导航站 x99dh 本身就是这个套路）。
3. **中文 URL 必须 quote**（禁漫 `/album/{id}/{中文slug}`、LissAV `/videos/genre/{中文}`、
   Hanime1 `/search?genre=裏番`），否则 `UnicodeEncodeError: 'ascii' codec`。
   tpl 里 `_page` 一般内置了非 ASCII 自动百分号编码。
4. **平台级 Tab 的 `cate` 是 `"0"`**，不是分类 id；非数字分类 id 的适配器要挡掉，否则抓 `/c/0` 得空。
5. **卡片 class 在同一站不同页可能变体**（Xanimu 首页 `thumb`、分类页 `thumb ppopp`）——
   正则一律写 `class="xxx[^"]*"`。
6. **卡片标题可能在 `img alt`**（LissAV国产区）、可能在**第二个同 href 的锚点的 title**（XVIDEOS），
   也可能在块内 `<span class="name">`（99漫画章节）。`TITLE_RE` 至少要覆盖 `aria-label|title|alt`。
7. **预览 ≠ 正片**：`preview.mp4`、`p320-180.mp4`、`trailer.mp4`、`data-preview`、`data-pvv` 都是悬停预览。
8. **签名直链有时效**：XVIDEOS `secure=` 约 4h、KVS 数小时～天级、Pornhub 分钟级。
   「抓完立即用」不可靠 → **`vod_play_url` 存详情页地址、`play()` 每次现取**。
9. **取 mp4 一定要 `read(N)` 限读**：CDN 会**忽略 Range 整段回源**，avjoy 的 480p 正片能把内存拉满
   （本轮踩过，卡死了一个测试进程）。
10. **站内页码可能比路径大 1**：XVIDEOS `/new/1` 的标题是「頁面 2」，`/new/0` 是 404。
    写分页前先确认偏移，别猜。
11. **协议相对地址 `//host/x`**：`_abs()` 已修；自己解析时别直接 `lstrip("/")` 拼本站。
12. 本机 `curl.exe` 对部分站点报 schannel 证书撤销错误——用 Python `ssl._create_unverified_context()`。
13. **别整读大响应**：`mod._http` 会把 body 全读进内存，抓 m3u8/JSON 可以，**抓 mp4 不行**。
14. **「图集」在审计里显示 OK ≠ 图能看**。Hentai 的旧 `detail` 有返回（审计打「图集」），
    但抽的是详情页的死缩略图 —— 这个缺陷靠审查看不出来。查图集类平台要看三件事：
    ```python
    # 1) URL 里 /galleries/{media_id}/ 是否和本画廊一致
    # 2) 文件名是不是 Nt.webp（t = thumb）、封面是不是 双后缀 cover.webp.webp
    # 3) 真去取一张看 HTTP 和字节数（原图几百 KB，缩略图几十 KB，尺寸也能从 webp 头读）
    ```
15. **CDN token「每页不同」≠ 不可复用——必须做内容级比对再下结论**。
    Hentai 阅读页里 token 逐页变（`nTxt` / `nTtt` / `nTpt` / `nTlt`），我据此误判成「逐页签名」，
    白写了一版逐页方案；**用 sha256 比对后发现同册内 token 完全通用**，2 次请求就能拿全册。
    以后遇到类似情况：先拿一个 token 去取别的页，**比字节/哈希**，别靠字符串形态推断。
    （同一现象里唯一为真的是：缩略图 token 套原图路径会 502 —— 那是资源目录不对。）
16. **「列表有数据」≠「适配完」**。要分四维看：列表 / 详情 / 分类（点进去**真的换内容**）/ 播放
    （**真拉流**，不是看 `vod_play_url` 的字符串形态）。第十二轮补充查出 5 个 bug 全是
    "看起来 OK"的：分类 chip 点了不换内容（MissAV 2/7、爱漫岛 1/8）、播放 URL 形态对但打不开
    （XVIDEOS 15/48 卡片）。
17. **写字卡链接要提防占位符**：XVIDEOS 有 1/3 的卡片 href 是字面量 `THUMBNUM`
    （站点用 JS 按当前缩略图替换），直接请求得 321 字节错误页。**列表抓完要抽一条真请求验证**。
18. **`homeContent` 绝对不能联网**。红线是 <50ms；一旦有平台在首屏联网，20 家就是 30s+
    （本轮实测 37.6s）。首屏只读缓存，抓取交给 `kick_refresh()` 后台；补分类的
    `scan_categories()` 还必须带**适配器 `categories()` 兜底**，否则新式路径的平台永远扫不到。
19. **maccms 分页路径要试出来，用卡片 id 集合判断是否真翻页**（别比字节哈希——页内广告会变）：
    爱漫岛 `/vodtype/{id}-{n}.html` 标题变了但内容与第 1 页逐字相同，真分页在
    `/vodshow/{id}--------{n}---.html`。
20. **改完分类/首屏逻辑一定要看「有没有丢东西」**：全量重建会按 `registry.py` 重生成 `classes`，
    快照里手改过的静态分类会被清掉（本轮 MissAV 的 7 个过期 id 和 爱漫岛 的 8 个就是这么暴露的）。
    重建前后 diff 一次 `classes` 与 `ok` 线路数。
21. **别让两条后台链路同时抓同一批站点**。`warm_first_tabs()` 原本用**联网的** `cats_for()`，
    和 `kick_refresh()` 在冷启动并发打同一批分类页；好几个站有频率限制（321 壳页），
    重复打容易踩雷。现在 `warm_first_tabs()` 只用**不联网的** `cats_cached_for()`，
    分类抓取唯一归 `kick_refresh()`，扫完再补一轮预热（按平台去重）。
22. **客户端没有的 UI，别急着在蜘蛛侧实现**。`homeVideoContent()` 是「首页推荐」的数据源，
    Swift 侧 `fetchHomeContent` 会在 `videos` 为空时调它（**20s 超时**），而 Flutter 侧
    `_loadHomeInternal()` **只看 `result.categories`、完全忽略 `result.videos`**。
    因为我们的 `list` 恒为空，这条 20s 分支**每次进首页都会走**——实现它等于给首屏埋雷。
    **先读客户端 UI 代码确认字段真被渲染，再决定要不要实现**。
23. **给客户端加字段要追到 UI 那一层**。来源平台标签打在 `vod_remarks`，能显示是因为
    `PythonSpiderEngine.parseVodItems` 用 `keys: ["vod_remarks","remarks","note"]` 取它，
    `WelfareResultMapper` 映射成 `vodRemarks`（注释就叫「角标」）。注意 `vod_id`/`vod_name`
    是**必需**字段，缺了整条被跳过；`vod_pic` 缺省补空串。
24. **「站点维护中」是按线路的，不是按站点的**。99漫画 的 `99mh.men` 的 `/enter` 正常，
    但同线路的 `/photos-index-aid-*.html` 回 321 维护页；而 `/photos-item-aid-*.html`
    **17 条线路全都可用**。所以：维护页出现时**要换线路**，不能 `return`（原实现两处
    `return ""` 把 18 条线路全短路，表现为「列表有数据、详情全空」）。
    **详情要接最稳的那个接口**，别接站点正在废掉的 HTML 页。
25. **自己写资源探针必须跟重定向**。CDN 直链基本都跳一次；不跟就会把好图判成 301 失败
    （爱漫岛 138 张图集就被误判过一次）。限读取流 + 跟 3 跳是标配。
26. **验「过期签名」要把时间戳换算出来**。99漫画 `verify=1793296800` → 2026-10-30 02:00
    → 过期 9 天 → 取图 404。把时间戳换算成日期再下结论，别只说「签名过期」。
27. **壳页的重试顺序是「先退避本线路，再换线路」**。禁漫的 2337 壳页是**按 IP 的限流**，
    换线路没用（同一出口）——原实现直接换 4 条线路，全失败就返回空，表现为**偶发 list 0 条**
    （连测其实是 70/70/69）。改成「本线路退避 1.2s/2.4s 重试 3 次 → 仍不行再换线路」后
    连测 **5/5 都是 70 条**。反过来，「站点维护中」是**按线路**的（99漫画），必须换线路。
    **两种壳页成因不同，处置顺序也不同，别混。**
28. **每家站点通常只有 1 集**。审计脚本里「抽 3 集」是假象——这些站一部作品就是一个视频，
    `vod_play_url` 只有 1 段。别拿「集数少」当 bug。
