# 密钥一键提取指南（crack_muse_key.py）

> 一条命令提取暮色(avbox)的 AES Key/IV。**不需要 Blutter、不需要编译环境、不需要真机。**
> App 更新后密钥变动，重跑本脚本即可，全程秒级。

---

## 一、快速开始

```bash
# 输入 APK（自动解包取 libapp.so）
python tools/crack_muse_key.py 暮色_1.0.1.apk

# 或直接输入已解出的二进制
python tools/crack_muse_key.py libapp.so          # 安卓 Dart AOT
python tools/crack_muse_key.py App                # iOS Dart AOT

# 输出到 JSON
python tools/crack_muse_key.py 暮色.apk --out key.json
```

**预期输出（暮色 1.0.1 实测）：**

```
[+] 命中 4 个候选：
    offset=0x0003CFDD  mask=0x1395  value=62233532ac9029c6   <== 独立常量
    offset=0x00078970  mask=0x1395  value=1f2b2cd0f9503f96      (来自32长串,参考)
    offset=0x00078990  mask=0x1395  value=0c2ad3f0194b4175      (来自32长串,参考)
    offset=0x0009729A  mask=0x1395  value=8992d27bceae2962   <== 独立常量
  判定: AES_KEY=8992d27bceae2962  AES_IV=62233532ac9029c6
  数据流: base64 → AES-128-CBC → gzip → JSON
```

两个「独立常量」就是 Key/IV；「32 长串」切片是请求签名的 MD5 盐
（拼起来 = `1f2b2cd0f9503f960c2ad3f0194b4175`），属于附赠情报。

## 二、工作原理

暮色把密钥以 **切罗基字母（Unicode U+13A0~U+13FF）UTF-16LE** 形式硬编码在
Dart AOT 快照里，运行时经 `StringExtension.s()` 逐码元 XOR `0x1395` 还原：

```
"ᎭᎬᎬᎧᏱᎧᎢ᏷᏶ᏰᏴᏰᎧᎬᎣᎧ"   --每码元 XOR 0x1395-->   "8992d27bceae2962"
```

脚本做的事：

1. 扫描二进制中所有 UTF-16LE 切罗基连续串
2. 只保留长度恰为 16（独立 Key/IV 常量）或 32（Key/IV 连体）的串
3. 先试已知掩码 `0x1395`；解不出则暴力 `0x0000~0xFFFF` 找出能还原成
   16 位 hex 的掩码（**暮色换掩码也能自动找回**）
4. 按 1.0.1 对象池布局判定：offset 小者=IV，大者=Key

---

## 三、退出码含义

| 退出码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功 | 直接用输出的 Key/IV |
| 1 | 参数错误 | 看 `--help`（不带参数运行） |
| 2 | **0 命中** | 混淆算法整个换了 → 回退《暮色逆向全流程方法.md》阶段 4（Blutter 全量反编译）找新混淆方式 |

## 四、拿到密钥后怎么用

1. 编辑 `sources/welfare-js/muse_avbox.py`：

   ```python
   AES_KEY = b"新的key"   # 16 字节
   AES_IV  = b"新的iv"    # 16 字节
   ```

2. **必须**跑 `python domain-monitor/merge_sources.py` 同步 all_sources.json（派生副本，App 只读它）
3. 提交两个文件一起推送远程源仓库
4. 用一段真实密文验证：base64 解码 → AES-CBC 解密 → 若 zlib/gzip 头（`1f8b`）出现即成功，
   解压后应见 `{"code":200,...}`

## 五、验证密文样本从哪来

- 安卓：`/data/data/com.look.mbox/` 下 sqlite / 文件缓存里的历史响应
- iOS：App 沙盒 Documents 下的 sqlite（本次样本来自 `iosnixiangzhushoutest.sqlite`）
- 或抓包：手机抓 `38.46.10.x:6868` 任一业务接口的响应体

## 六、常见问题

**Q：为什么不需要 Blutter 了？**
Blutter 的作用是"发现"混淆算法。算法已知后（切罗基 + XOR 掩码），
字节级模式匹配就能完成同样的事，且快百倍、零依赖。

**Q：如果新版把切罗基换成了别的 Unicode 区段？**
脚本 0 命中时，回到全流程文档阶段 4，用 Blutter 读 `StringExtension.s()`
的新实现，改脚本里的 `CHEROKEE_LO/HI` 和 `DEFAULT_MASK` 三个常量即可。

**Q：Key/IV 判定反了怎么办？**
交换 `muse_avbox.py` 里的两个值即可（解密失败通常表现为 gzip 头 `1f8b` 不出现）。
